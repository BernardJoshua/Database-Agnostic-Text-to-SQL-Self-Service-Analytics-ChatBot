Product Overview

Summary

The proposed application uses semantic parsing in NLP to convert natural language into SQL while adapting to different database structures. It is designed as a self-service analytics assistant so non-technical users can ask business questions directly and receive structured, query-backed outputs.

Problem Statement

What this project fixes

Inefficient Resource Usage

Data analysts and engineers are repeatedly interrupted by simple ad hoc requests instead of focusing on higher-value work.

Decision Delays

Slow turnaround for request handling and SQL generation delays timely business decision-making.

Technical Dependency

Non-technical stakeholders rely too heavily on technical teams for basic data access and business insight retrieval.

Objectives

Core product goals

  • Convert natural-language queries into SQL statements.
  • Enable self-service data access for non-technical stakeholders.
  • Reduce dependency on data analysts and engineers for routine ad hoc queries.
  • Support database-agnostic behavior across varying schemas.
  • Rigorously evaluate SQL accuracy, executability, and system usefulness.

Success Metrics

  • Execution Accuracy
  • Retrieval Relevance
  • SQL Correctness
  • Error Analysis
  • Response Time

Stakeholders & Target Users

Who this is for

Primary users

Marketing Growth Strategy Finance / Treasury HR

Pain points

  • Need to wait for data teams to answer routine requests.
  • Slow speed of information retrieval for decision-making.
  • SQL learning curve blocks direct self-service access.

User Stories

Example business asks

As a marketing analyst, I want to know what the conversion rate for the New-Year's campaign looks like in percentage.

As a strategy analyst, I want to get the month-on-month growth rate of Product A.

As a financial or treasury analyst, I want to estimate the acquisition cost of Company B based on similar companies acquired in the past year.

As an HR analyst, I want to track employee churn over the past 5 months.

Scope Definition

What the product does and does not do

In Scope

  • SQL-based analytics workflows
  • SELECT queries
  • Aggregations
  • Joins

Out of Scope

  • Non-SQL analytics such as Python or Spark workflows
  • Full data pipeline design or engineering
  • Building base tables
